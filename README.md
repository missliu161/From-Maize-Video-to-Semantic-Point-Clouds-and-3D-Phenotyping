# From Maize Video to Semantic Point Clouds and 3D Phenotyping

This repository provides code for running 2D Gaussian Splatting (2DGS), semantic point-cloud processing, trunk extraction, and 3D phenotyping from either a video or existing COLMAP poses.

## Workflow

```text
Video → frame extraction → VGGSfM pose estimation → 2DGS and semantic segmentation
      → point-cloud post-processing → trunk extraction → phenotyping results (PLY, Excel)
```

If COLMAP poses and images are already available, frame extraction and VGGSfM can be skipped and the workflow can start from 2DGS.

## Environment

The complete workflow requires Linux x86_64, Conda, an NVIDIA GPU and driver, CUDA Toolkit 11.8 (including `nvcc`), and GCC/G++ 11 or earlier. `setup_environment.sh` creates a new Conda environment named `gsid-seg` by default, installs the 2DGS and post-processing dependencies, builds the CUDA extensions, and checks the environment.

Run the following commands from the repository root:

```bash
bash setup_environment.sh
conda activate gsid-seg
python check_environment.py
```

If `gsid-seg` already exists, choose a different environment name:

```bash
GSID_ENV_NAME=gsid-seg-new bash setup_environment.sh
conda activate gsid-seg-new
```

VGGSfM uses a separate environment and is not installed by this setup script. The pinned Python and package versions are specified in [`2dgs/environment.yml`](2dgs/environment.yml) and [`2dgs/requirements.txt`](2dgs/requirements.txt).

## Run the complete video workflow

Run the following command from the repository root with a new scene directory. The complete workflow also requires a checkout of the [official VGGSfM repository](https://github.com/facebookresearch/vggsfm) and a separate environment installed according to its documentation. Provide the VGGSfM source directory and Python executable when running the workflow.

```bash
conda activate gsid-seg
python run_end_to_end.py \
  /path/to/input_video.mp4 \
  data/scenes/my_scene \
  --vggsfm-dir /path/to/vggsfm \
  --vggsfm-python /path/to/vggsfm-env/bin/python \
  --gs-python "$CONDA_PREFIX/bin/python"
```

By default, two frames per second are extracted from the video, VGGSfM is run on the number of images actually extracted, and 30,000 training iterations are used. The scene directory may be stored outside the repository. Use `--sampling-fps` to change the frame-sampling rate. If a corresponding training result already exists, add `--skip-train`; to recompute the denoised point cloud, add `--overwrite`. See `python run_end_to_end.py --help` for additional options.

## Run from existing poses

The scene directory must contain `images/` and a COLMAP-format `sparse/0/` directory with `cameras`, `images`, and `points3D` files in either `.bin` or `.txt` format.

```bash
conda activate gsid-seg
python run_from_poses.py /path/to/scene
```

If the scene already contains `output/point_cloud/iteration_30000/point_cloud.ply`, add `--skip-train`. This entry point does not require VGGSfM and does not extract video frames.

## Main outputs

Results are written to the scene directory:

```text
semantic_matchin/point_cloud_object_post.ply
semantic_matchin/point_cloud_object_post_split.ply
point_cloud_sphere_denoised.ply
point_cloud_trunk.ply
phenotype_results/<scene>_B.ply
phenotype_results/<scene>_phenotype.xlsx
```

The sphere-cropped point cloud is passed to DBSCAN in memory and is not saved as an intermediate PLY. The scene root contains only the denoised `point_cloud_sphere_denoised.ply`. Length and area calibration uses semantic point-cloud object `221` as the reference object; verify that the class ID matches the model mapping before running the workflow.
